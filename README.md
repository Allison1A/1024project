# 宠物投保唯一识别（OPEN-SZ-02）

> 文档状态：**2026-10-12 全量复核**（基于仓库代码 + 实验记录逐条对账；同日已将 Track A 全链路合并入库）· 初赛**10/14** · 决赛 **10/22**

**命题**：用户投保时提交**正脸照 + 全身照**，系统判断二者是否为同一只宠物，用于投保建档与理赔核身。

**本质**：开放集个体识别（open-set Re-ID），**不是图像分类**。

## 1. 命题验收标准与实际对账

### 1.1 五项验收标准

| 验收项 | 要求 | 实际 | 判定 |
| --- | --- | --- | --- |
| 响应速度 | ≤ 2 秒 | 416ms（**非最终配置**：DINOv2-base@224 + YOLOv8n416；方案已改 448，须重测） | ⚠️ 有 4.8× 余量但口径不对 |
| 同宠识别率 | ≥ 95% | 59.18%（严口径，DINOv2 零训练） | ❌ 差 11~36pp |
| 异宠区分率 | ≥ 98% | 非独立指标——所有识别率都报在 FAR≤2% 工作点上，**两个准确率在同一阈值下同时满足** | ✅ 口径已对齐 |
| 品种覆盖 | ≥ 10 种 | 28 种（狗 18 + 猫 10，Chinese-CLIP 零样本打标） | ✅ 但口径偏软，见 §3.5 |
| 鲁棒性 | 模糊/逆光/跨龄/遮挡 | 零量化证据 | ❌ |

> **两项准确率必须在同一阈值下同时满足**。识别率与区分率是同一根 ROC 曲线上的两点，分别调阈值能让任一指标好看，但不能同时达标。本项目固定**单一阈值 τ**，两指标在该 τ 下同时报告。

## 2. 两条技术线与两套口径

### 2.1 两条技术线（Track A / Track B）

| | **Track A** | **Track B** |
| --- | --- | --- |
| 骨干网 | DINOv2-small / base（Meta） | NextViT-base `nextvit_base.bd_ssld_6m_in1k` |
| 路线 | **零训练**，直接用通用特征 + 余弦相似度 | **域内微调**，Triplet + BatchHardMiner |
| 代码位置 | 本仓库（`stage0~stage5`、`report_far2.py` 等） | 本仓库（`finetune_crosspose.py` 等） |
| 产物位置 | 嵌入 `.npy` 已入库 | `ckpt_crosspose/`，**目前不存在** |
| 最好结果 | 59.18%（严口径 @FAR2%） | 84.19%（字面口径 @FAR2%） |

### 2.2 严口径 vs 字面口径

| | **严口径（主）** | **字面口径（并行）** |
| --- | --- | --- |
| 正样本 | 同体 front ↔ overall | 同体 front ↔ overall |
| 负样本 | 异体**同姿态** `max(sim(Fᵢ,Fⱼ), sim(Oᵢ,Oⱼ))`，限同物种 | 异体**跨姿态** `A.front ↔ B.overall`，限同物种 |
| 负对规模 | **约 50 万对** | **267 对**（正负 1:1 配平） |
| 实现位置 | `stage0_detect_crop.py::build_scores` | `baseline_target_domain.py::build_cross_pose_pairs` |
| 对应数字 | **59.18%** | **84.19%** |

**为什么严口径更难**：字面口径的负对被强行塞进了姿态差异，姿态本身就会压低相似度——模型只要学会「分姿态」就能得分，**身份判别力被掩盖**，指标偏乐观。严口径消除姿态变量、负对纯比身份，是更保守的压力测试。

**字面口径还有第二个乐观偏差**：267 个负对意味着 FAR=2% 的阈值只由**最难的那约 5 个负样本**决定（TPR 粒度 0.37%），bootstrap 95% CI 约 **±4.4pp**。方案稿 §5.1 自己要求「所有主指标附负对规模与 bootstrap 95% CI」，§5.2 自己写明「Literal 层数字天然偏高，不作为内部选型依据」——**当前 84.19% 这个数字按团队自己的纪律是不能用于对外结论的**。

### 2.3 Track B 的锚点链（同口径，可直接引用）

held-out 267 个体 / 534 对，seed=42，img_size=224：

| 锚点 | 配置 | AUC | TPR@FPR2% |
| --- | --- | --- | --- |
| X | 零训练 NextViT | 0.9466 | **57.30%** |
| Y | Run A e1（公开数据预训练后） | 0.9680 | **59.93%** |
| — | 业务域微调 20 轮（从 Y 起步） | 0.978~0.983 | 峰值 **85.77%**（e16） |
| — | 微调 e11~e20 均值（**无偏估计**） | — | **84.19%** |

**取值纪律**：85.77% 是用 test 集选轮次选出来的，偏乐观；对外应使用 **84.19%（平台期均值）**，或按 §5.1 要求切独立 val 后重选。

**一个正面信号**：从零训练 NextViT 起步时 e1 即是峰值、之后单调下降；从公开数据预训练权重起步后变成**震荡上行并进入平台**——说明微调确实在学跨姿态不变性，不是在拟合训练集。

## 3. 已验证结论（不要重新推导）

以下结论都已跑过实验，**重跑前请先读本节**，避免重复投入。

### 3.1 病因定位：瓶颈是跨姿态鸿沟（核心结论）

在 DogFaceNet（1392 只狗 / 7415 张**已对齐脸部裁剪图**）上，用**完全相同**的评测口径和**同样的零微调模型**评测：

| 场景 | 同宠识别率@异宠 98% | AUC | EER |
| --- | --- | --- | --- |
| 业务数据：正脸 ↔ 全身 | 59.18% | 0.9485 | 12.97% |
| **DogFaceNet：脸 ↔ 脸（跨场景）** | **90.93%** | **0.9909** | **4.16%** |

样本量：17845 正对 / 199.7 万负对。差距 **31.75pp**，一举排除三种假设：

- ❌ 不是骨干网通用特征不足 —— 否则 DogFaceNet 也该只有 59%
- ❌ 不是跨场景/跨光照难 —— DogFaceNet 本身即跨场景，仍有 90.93%
- ❌ 不是「投保时拍 vs 理赔时拍」的时间跨度 —— 同上
- ✅ **就是正脸↔全身的跨姿态鸿沟**

**价值**：把「要全面提升模型」的模糊问题，变成「**只需补姿态归一化**」的定向工程问题，并给出该问题解决后的能力上限参考（90.93%，距 95% 仅 4.07pp）。

> ⚠️ 该对照**只覆盖狗**，猫尚无同类验证。

### 3.2 背景捷径已证伪

担心模型在吃背景（同次拍摄的两张图共享背景、光线、项圈）。按**上传时间间隔**分层构造负样本：

| 时间层 | 负对均值 |
| --- | --- |
| 同批次（0 天） | 0.3090 |
| ~1 天 | 0.3044 |
| ~2 天 | 0.2989 |
| ~3 天 | 0.3009 |
| ≥4 天 | 0.3053 |

各层均值极差仅 **0.0101** → **模型没在吃背景**。脚本 `stage5_time_strata.py`。

> ⚠️ 局限：业务数据时间跨度仅 **4.47 天**，无法覆盖长周期场景。

### 3.3 裁头已排除（负面结果，不要重跑）

想用「COCO 全身框按几何比例猜头部」零成本替代面部检测。结果：

| 头部裁剪比例 | 同宠识别率@FAR1% |
| --- | --- |
| 基线（全身框） | 50.80% |
| 0.35 | 28.04% |
| 0.45 | 36.63% |
| 0.55 | 41.22% |

非对称组合穷举 **25 种，增益 +0.00pp**。可视化印证：站姿/坐姿命中良好，**趴卧/侧身完全失效**。

**结论**：按框几何分层诊断，裁头在**所有**子群体都变差，不存在「某类样本适用」。**失败的是「用 COCO 全身框猜头部」这个替代实现，不是脸↔脸路线本身**（后者有 §3.1 的 90.93% 背书）。这条负面结果省下了错误方向的投入，也证明本题**不存在零成本捷径**。

### 3.4 猫狗同源性：负样本尾部一致

| 物种 | 同宠识别率@FAR2% | 负样本均值 | **负样本 P99** |
| --- | --- | --- | --- |
| 猫 | 55.63% | 0.3944 | **0.7262** |
| 狗 | 62.30% | 0.2418 | **0.7297** |

负样本**均值**差异大，但 P99 尾部高度一致——真正决定低 FAR 工作点的是尾部，故**猫狗同源，可用同一阈值**。反事实检验：交叉阈值上下调 ±1pp，结论不变。

> 📌 方法学教训：早期基于**均值**得出的「猫狗不同源」结论是**错的**，改用尾部 P99 后才修正过来。低 FAR 指标由少数最难负样本决定，看均值会误判。

### 3.5 延迟与品种覆盖

**延迟**（i5-10505 / 6 线程 / CPU / ONNX Runtime 全核 / 预热 2 次取 5 次均值）：

| 配置 | 端到端 | 余量 | 状态 |
| --- | --- | --- | --- |
| DINOv2-base@224 双图 INT8 | 274ms | — | ✅ 实测 |
| DINOv2-small@224 双图 INT8 | 90ms | — | ✅ 实测 |
| YOLOv8n@416 双图检测 | 269ms | — | ✅ 实测 |
| **base@224 + YOLOv8n416 端到端** | **416ms** | 4.8× | ✅ 实测 |
| base@448 + YOLOv8n416 | ~1.4s | 1.4×（偏紧） | ⚠️ 估算 |
| small@448 + YOLOv8n416 | ~0.63s | 3.2× | ⚠️ 估算 |

**检测环节占总耗时 65%**，优化空间在检测侧（降检测输入分辨率 / 复用框缓存），不在特征提取侧。
方案已采纳 448 输入（计算量约 224 的 4 倍），**必须以最终配置重测**——用不会上线的配置测延迟是常见失误。

**品种覆盖**：命题要求「≥10 种常见猫狗品种」，需分清三层——物种（cat/dog，2 类）、**品种 breed（命题所指这一层）**、花色 coat（橘猫/三花，实为毛色表现，不计入）。用 Chinese-CLIP 零样本对全部 2004 张打标：**狗 18 种 + 猫 10 种 = 28 种**，余量充足。

**同一实验暴露的噪声**：同一只宠物的两图必然同品种，但零样本模型仅 **猫 62.25% / 狗 74.68%** 判为一致——泰迪↔比熊、短毛猫间互混严重。
**推论：本题不能靠品种特征做识别**，品种内个体差异大、跨品种形态又大量重叠，只有个体级度量学习立得住。

### 3.6 数据自洽

按**个体 ID** 划分 train/test 并物种分层，已验证**跨 split 个体数 = 0**，无数据泄漏。

## 4. 代码地图

### 4.1 Track B：训练链（本仓库根目录）

| 文件 | 作用 | 关键依赖 |
| --- | --- | --- |
| `model.py` | `PetEmbeddingNet`（骨干网 + 512 维嵌入头 + L2 归一化）、`ZeroShotBackbone`（红线 7 对照线，不降维）、`build_triplet_loss(margin=0.3)` | `timm`、`pytorch_metric_learning` |
| `dataset.py` | 命题方数据集读取、增强（KR5：翻转/仿射/亮度对比度/HSV/CoarseDropout/模糊抖动） | `albumentations`、`cv2` |
| `sampler.py` | `SpeciesPKBatchSampler` —— **同物种内**做 P×K 组批 | — |
| `baseline_target_domain.py` | 目标域零训练基线，**定义字面口径**（`build_cross_pose_pairs`） | `sklearn` |
| `finetune_crosspose.py` | **核心训练脚本**：NextViT + Triplet + BatchHardMiner，20 轮 | 全部上述 |

**为什么用 Triplet 而不是 ArcFace**：业务数据每个体仅 2 图（K=2），P×K 采样支撑不起类中心学习，ArcFace 在 4 万个体规模下会崩。Triplet 直接优化「同体 − 异体」的**差值**，与主指标 TPR@FAR 所度量的量一致，且不建类中心，个体数不进入优化难度。

**为什么同物种内组批**：使批内挖掘到的最难负样本恰为「同物种异体」，与评测 Hard 层一致。否则模型只学会「分物种」，一遇同物种异体即失效。

**红线**：
- 红线 1 —— 按个体 ID 划分，禁止跨 split
- 红线 4 —— 分组学习率（`backbone_lr=1e-5` / head `lr=1e-3`）
- 红线 7 —— 任何训练结果必须与零训练基线对比

### 6.5 中文路径读取陷阱

Windows 下 `cv2.imread` 遇非 ASCII 路径**静默返回 None**。必须：

```python
cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)
```
